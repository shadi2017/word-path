# كلمة · رحلة كل يوم

موقع عربي لقراءة الكتاب المقدس، جاهز للربط بـSupabase والنشر على GitHub Pages. لا يحتاج تثبيت حزم لتشغيل الواجهة.

## الموجود

- خطط للـ66 سفر / 1189 إصحاح، بأي مدة من يوم إلى 10 سنوات، متنوعة أو بترتيب الأسفار.
- التقسيم بالشهور والأيام، حفظ كل إصحاح مقروء، وإعادة توزيع الخطة دون فقد التقدّم.
- النص العربي الكامل لفان دايك داخل الموقع.
- خلفية لكل سفر، وسياق القسم الذي يحتوي الإصحاح. هذه مداخل موجزة وليست تفسيرًا تفصيليًا لكل إصحاح.
- قاموس أولي للكلمات الصعبة، و133770 إحالة للآيات المقابلة موزّعة على جميع الإصحاحات، حتى خمس إحالات لكل آية لها بيانات.
- 945 آية في مجموعة الرسائل اليومية. المحتوى مأخوذ حرفيًا من نص الكتاب، مع المرجع.
- تسجيل بالبريد وكلمة المرور، وتأكيد بريد، ثم انتظار موافقة الأدمن.
- اسم مستخدم فريد، بحث بين الأعضاء المقبولين، عرض خططهم وتقدّمهم وتشجيعهم بتعليق.
- أدمن يقبل أو يرفض الأعضاء ويعيّن أدمن آخر وينشئ مجموعات ويضيف ويحذف عضوية الأفراد.
- تفضيلات اختيارية للآية اليومية وتذكير القراءة الفائتة، ورسالة واحدة للمستخدم في اليوم.
- نسخة احتياطية قابلة للتنزيل من تقدّم المستخدم، ومظهر مناسب للموبايل.

## الحالة

الواجهة تعمل محليًا، وتم ربط `public/config.js` بمشروع Supabase `fokhgddvypmzxbsbncvy` باستخدام المفتاح العام فقط، وتطبيق `supabase/schema.sql` بنجاح يوم 2026-09-21. لا تعِد تشغيل مخطط الإنشاء على هذا المشروع. تم التحقق من أن التسجيل وتأكيد البريد مفعّلان وأن الاستدعاء المجهول لوظائف الحساب والإرسال مرفوض. حساب الأدمن يحتاج أن يسجله صاحبه ويؤكد البريد أولًا ثم يُعيّن من قاعدة البيانات. رابط العودة الحالي للتأكيد هو المعاينة المحلية؛ يجب تحديثه إلى رابط GitHub Pages النهائي بعد النشر.

وضع «استكشف نسخة تجريبية» يستخدم بيانات مؤقتة في الذاكرة، لا يدّعي حفظًا سحابيًا ولا يرسل رسائل. **الموقع لم يُنشر على GitHub بعد، والإيميلات اليومية لم تُفعّل.**

## تشغيل محلي

من مجلد المشروع:

```powershell
node scripts/serve.mjs
```

ثم افتح http://127.0.0.1:4173 . الاختبارات: `node --test tests/planner.test.mjs`.

## 1. ربط Supabase

1. للمشاريع الجديدة فقط: افتح Supabase ثم SQL Editor وشغّل `supabase/schema.sql` مرة واحدة. تم تنفيذها بالفعل للمشروع الحالي. المخطط يستخدم schema خاصة اسمها `private`، وكل التعامل من وظائف تتحقق من صلاحيات المستخدم في الخادم. لا تضف `private` إلى Exposed schemas.
2. من Project Settings → API انسخ Project URL وPublishable key (أو المفتاح القديم anon)، وضعهما في `public/config.js`.
3. **ممنوع وضع service_role أو secret key في الواجهة أو المستودع.** المفتاح العام آمن مع الصلاحيات المضمّنة؛ المفتاح الخدمي يتخطّى صلاحيات المستخدم.
4. من Authentication فعّل تأكيد البريد. اضبط Site URL وRedirect URLs على عنوان GitHub Pages النهائي، بنفس مسار المستودع، مثل `https://YOURNAME.github.io/YOURREPO/`، وأضف عنوان التطوير المحلي إن احتجت.
5. اضبط SMTP مخصصًا لرسائل التسجيل واستعادة كلمة المرور قبل دعوة الناس؛ مزوّد Supabase الافتراضي مخصص للاختبار وحدوده لا تناسب تسجيل جمهور عام. يمكن استخدام بيانات SMTP من Resend بعد توثيق نطاق إرسال تملكه.
6. سجّل حسابك من الموقع وأكّد البريد. لإنشاء **أول أدمن فقط**، شغّل SQL الآتي بعد تغيير البريد إلى بريدك المؤكّد. لا تمنح الأدمن تلقائيًا لأول من يسجل:

```sql
update private.profiles p
set role = 'admin', status = 'approved'
from auth.users u
where p.id = u.id
  and u.email = 'YOUR_CONFIRMED_EMAIL'
  and u.email_confirmed_at is not null;
```

7. حدّث الصفحة. بقية طلبات القبول وإدارة المجموعات تتم من لوحة الإدارة. الأعضاء المنتظرون والمرفوضون لا يمكنهم استدعاء وظائف القراءة الاجتماعية أو حفظ التقدّم حتى لو حاولوا تجاوز الواجهة.

## 2. النشر على GitHub Pages

1. ارفع محتويات مجلد `word-path` إلى مستودعك على فرع `main`. المستودع العام يناسب الاستضافة المجانية على GitHub Free. لا ترفع ملفات الأسرار أو test-tools أو sources.
2. Settings → Pages → Source → GitHub Actions.
3. شغّل Publish Kalima أو ادفع تحديثًا إلى `main`. ملف `.github/workflows/pages.yml` ينشر مجلد `public` فقط بعد الاختبارات.
4. بعد ظهور الرابط، ضعه في إعدادات Auth في Supabase. الواجهة تستخدم روابط نسبية وتدعم النشر تحت مسار مستودع.

## 3. الآيات اليومية وتذكير القراءة

1. جهّز Resend مع نطاق إرسال موثّق وعنوان From. خطة الإرسال مجانية ضمن الحصة، **لكن شراء نطاق غير مملوك بالفعل قد تكون له تكلفة مستقلة**. نطاق Resend التجريبي لا يصلح لإرسال الرسائل لكل الأعضاء.
2. في GitHub Settings → Secrets and variables → Actions أضف Repository secrets:
   - `SUPABASE_URL`
   - `SUPABASE_SERVICE_ROLE_KEY` (في الأسرار فقط)
   - `RESEND_API_KEY`
   - `EMAIL_FROM` مثال: `Kalima <daily@your-domain.com>`
3. أضف Repository variables: `SITE_URL` بعنوان الموقع النهائي و`EMAIL_ENABLED` بقيمة `true` بعد اختبار الإرسال لحسابك.
4. وظيفة Daily verse and gentle reminder تعمل 3 مرات قرب المساء، وتتحقق من توقيت القاهرة (بما فيه الصيفي). لا ترسل خارج 20:00–22:59، وتستخدم سجل إرسال ومفتاح idempotency لمنع التكرار. تأخير GitHub Actions ممكن؛ الوقت ليس مضمونًا بالدقيقة.
5. يُرسل التذكير عند وجود إصحاحات غير مقروءة **حتى اليوم السابق**، وليس لمجرد أن المستخدم لم يفتح الموقع. يتم دمجه مع آية اليوم في رسالة واحدة. كل التفضيلات متوقفة افتراضيًا، ويمكن تعطيلها من الإعدادات.
6. سقف التطبيق 90 رسالة في اليوم، ليترك هامشًا من حصة Resend المجانية المعتادة 100/يوم و3000/شهر. لو زاد المستخدمون على ذلك، لا يضمن وصول رسالة يومية للجميع. راجع الحدود الحالية وأي إرسال آخر من حسابك.
7. GitHub قد يوقف التشغيل المجدول في المستودعات العامة بعد فترة من عدم النشاط؛ راجع Actions دوريًا. Supabase Free قد يوقف المشروع بعد عدم النشاط. للحصول على تذكير يومي مضمون واستمرارية أعلى، قد تحتاج خدمة مدفوعة لاحقًا.

## الحفاظ على البيانات

حالة التقدّم والخطط موجودة في PostgreSQL، وليس في تخزين المتصفح. التخزين المحلي يستخدم لجلسة الدخول فقط؛ فتح الحساب نفسه على جهاز آخر يعيد التقدّم. تنزيل نسخة المستخدم من الإعدادات متاح، واعمل أيضًا نسخ قاعدة بيانات دورية خارج الخدمة. الخطة المجانية لا تعني ضمانًا مطلقًا ضد الحذف أو التعطّل. لا تعدّل مخطط قاعدة البيانات مستقبلًا بإعادة تشغيل ملف الإنشاء؛ استخدم ترحيلات منفصلة.

## القراءة والتوثيق

راجع `ATTRIBUTION.md` لمصادر النص والإحالات وترخيصها. شرح الكلمات محدود وتحريري، وليس قاموسًا شاملًا، ومداخل السياق لا تنسب إلى مفسّر. الآيات اليومية منتقاة من مقاطع للتأمل والرجاء والتعليم، وليست كل آية وعدًا شخصيًا منفصلًا عن سياقها.

## اختبارات مطلوبة بعد الربط

جرّب بحسابين تجريبيين: طالب انضمام لا يمكنه الوصول قبل القبول؛ أدمن يقبله؛ حفظ التقدّم ثم تسجيل الخروج والدخول من جهاز آخر؛ البحث والخطة والتشجيع؛ مجموعة لها عضو وغير عضو؛ سحب القبول يمنع الوصول فورًا؛ تشغيل الإيميل مرتين لا يكرره؛ إيقاف التفضيلات يمنع الرسائل. لم يتم اختبار اتصال مشروعك الحقيقي قبل الحصول على روابطه وربطه.
